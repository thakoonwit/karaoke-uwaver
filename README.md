# 📻 VRS Office Radio - ระบบเว็บขอเพลงเปิดในออฟฟิศ

**VRS Office Radio** เป็นระบบเว็บขอเพลงสำหรับใช้งานภายในออฟฟิศแบบง่าย มินิมอล และใช้งานได้จริง **โดยไม่ใช้ Discord** รันบนคอมพิวเตอร์ Windows เครื่องเดียว พนักงานสามารถขอเพลงผ่านมือถือในวง Wi-Fi เดียวกัน จากนั้น iPhone/อุปกรณ์กลางออฟฟิศที่เปิดหน้า **`/player`** ค้างไว้จะเล่นวิดีโอเพลงตามคิวผ่าน **YouTube IFrame Player API** ออกลำโพง Bluetooth ออฟฟิศโดยตรง

---

## ปรับเสียง Player จากเครื่องอื่น

1. เปิดหน้า `/player` บน Android แล้วแตะเริ่มเปิดเพลง
2. เปิดเว็บระบบเดียวกันที่ `/admin` จากมือถือหรือคอมพิวเตอร์อีกเครื่อง แล้วเข้าสู่ระบบด้วย PIN
3. เลื่อนแถบ **ระดับเสียง Player** แล้วปล่อยเพื่อส่งค่า 0–100% (0% คือเงียบ)

ระบบบันทึกระดับเสียงไว้เมื่อเปลี่ยนเพลง รีเฟรช Player และรีสตาร์ตเซิร์ฟเวอร์ หาก Player ออฟไลน์ ค่าจะถูกใช้เมื่อกลับมาเชื่อมต่อ การปรับนี้ควบคุมเสียงเพลงในเว็บ ส่วนระดับเสียง Android และลำโพงยังเป็นตัวกำหนดความดังสูงสุด ควรทดสอบกับเบราว์เซอร์บน Android ที่ใช้งานจริง

## ประวัติคำขอเพลงวันนี้ของทุกคน

เลือกแท็บ **วันนี้ของทุกคน** ถัดจาก **ฮิตออฟฟิศ** ในหน้าหลัก เพื่อดูชื่อเพลง ผู้ขอ เวลา และชื่อเพลย์ลิสต์ (ถ้ามี) โดยไม่ต้องออกจากหน้า เรียงจากล่าสุด ใช้วันและเวลาไทย `Asia/Bangkok` และอัปเดตเมื่อคิวเปลี่ยน รวมถึงตรวจใหม่ทุกนาทีขณะเปิดหน้าเว็บ ลิงก์ `/history` เดิมยังเปิดได้

ประวัติบันทึกเฉพาะคำขอที่เพิ่มสำเร็จ ไม่รวม Auto-DJ และยังอยู่แม้เพลงถูกลบหรือล้างออกจากคิว เก็บเฉพาะคำขอของวันปัจจุบันในไฟล์ข้อมูลเดิม เมื่อเริ่มใช้ฟีเจอร์นี้จะนำรายการของวันนี้ที่ยังเหลือในคิว เพลงปัจจุบัน และประวัติเดิมมาแสดงด้วย รายการเก่าที่เคยถูกลบหรือไม่ได้เก็บไว้แล้วไม่สามารถกู้กลับมาได้

## เลื่อนลำดับคิวเพลงใน Admin

หลังเข้าสู่ระบบ `/admin` ใช้ปุ่มลูกศรขึ้น/ลงข้างแต่ละเพลงเพื่อย้ายทีละหนึ่งลำดับ ปุ่มขึ้นของเพลงแรกและปุ่มลงของเพลงสุดท้ายจะถูกปิดไว้ ระบบบันทึกลำดับใหม่และอัปเดตทุกเครื่องผ่านการเชื่อมต่อเดิม การย้ายมีผลเฉพาะเพลงที่รอเล่น ไม่เปลี่ยนเพลงปัจจุบันหรือประวัติคำขอ หากเพลงถูกเล่นหรือลบไปก่อนแล้ว ระบบจะปฏิเสธคำสั่งย้ายรายการนั้น

## Render: ลดการใช้ RAM

- ตั้ง Start Command เป็น `npm run start:render` เพื่อจำกัด JavaScript heap ที่ 256 MB (ไม่ใช่เพดาน RAM รวมของโปรเซส)
- ตั้ง `ENABLE_DIRECT_AUDIO=false` หรือไม่กำหนดค่านี้ก็ได้: Player ปัจจุบันเล่นผ่าน YouTube IFrame ในเบราว์เซอร์ ไม่จำเป็นต้องดึงหรือส่งเสียงผ่านเซิร์ฟเวอร์
- ระบบไม่ดึงเสียงล่วงหน้าทุกครั้งที่อัปเดตคิวแล้ว จึงไม่สร้างโปรเซส `yt-dlp` ระหว่างการเล่นปกติ
- จำกัดงานค้นหาพร้อมกัน 2 งาน แคชผลค้นหา 100 รายการ และกำหนดเวลา/ขนาดสูงสุดของข้อมูลที่ดึงจาก YouTube หากงานเต็มจะตอบให้ลองใหม่ แทนสะสมงานไม่จำกัด
- จำกัดประวัติการเล่นใน RAM ที่ 200 รายการตามขีดจำกัดไฟล์เดิม และล้างตัวจับเวลาขอเพลงของอุปกรณ์ที่ไม่ได้ใช้งานเกินหนึ่งวัน ประวัติคำขอรวมของวันนี้ยังเก็บแยกตามเดิม
- หน้าหลักใช้ Socket.IO เพียงการเชื่อมต่อเดียวต่อแท็บ และจะโหลดประวัติรวมเฉพาะเมื่อเปิดแท็บประวัติ เพื่อลดทั้งการเชื่อมต่อและการสร้างข้อมูลตอบกลับที่ไม่จำเป็น

หากมีไคลเอนต์เก่าที่ใช้ `/api/stream/:videoId` ต้องเปิด `ENABLE_DIRECT_AUDIO=true` เอง ซึ่งจะเพิ่มการใช้ RAM: จำกัดการดึง URL ครั้งละหนึ่งโปรเซส รวมคำขอซ้ำ จำกัดเวลา 20 วินาทีต่อครั้ง แคช URL ไม่เกิน 32 รายการ และจำกัดสตรีมพร้อมกัน 2 สาย ตัดการเชื่อมต่อต้นทางเมื่อผู้ฟังตัดการเชื่อมต่อ ข้อผิดพลาดประเภทถูก YouTube บล็อก/ต้องยืนยันตัวตนจะไม่เริ่มโปรเซสสำรองซ้ำ

หลัง deploy ให้ตรวจ Metrics และ log บน Render อีกครั้ง การทดสอบในเครื่องไม่ยืนยันว่าอาการ crash ทุกกรณีมาจาก RAM และพื้นที่ไฟล์บน Render Free ยังคงเป็นพื้นที่ชั่วคราวตามเดิม

## 🌟 ฟีเจอร์หลัก

- 📱 **Mobile-First Request Page (`/`)**: หน้าเว็บขอเพลงสวยงาม ใช้งานง่าย โทนสีน้ำเงิน-ขาว ภาษาไทยทั้งหมด รองรับทั้ง iPhone และ Android
- 🌙 **Dark Mode Support**: มีปุ่มสลับ Dark Mode ถนอมสายตา และจดจำการตั้งค่าในอุปกรณ์
- 📻 **Central Web Player (`/player`)**: หน้าเครื่องเล่นเพลงสำหรับเปิดค้างไว้บน iPhone เครื่องกลางที่ต่อกับลำโพง Bluetooth
- ⚡ **Real-time Synchronization**: คิวเพลง สถานะ Player และสถานะเพลงกำลังเล่น อัปเดตสดด้วย Socket.IO โดยไม่ต้องรีเฟรชหน้า
- 🔍 **YouTube Data API v3**: พิมพ์ชื่อเพลงเพื่อค้นหา หรือวางลิงก์จาก `youtube.com`, `youtu.be`, `music.youtube.com` ได้ทันที
- 🛡️ **กฎการขอเพลงและความปลอดภัย**:
  - คนหนึ่งมีเพลงในคิวรอได้ไม่เกิน 2 เพลง (จำกัดด้วย Device ID ใน Local Storage)
  - เว้นระยะการขอเพลงอย่างน้อย 2 นาทีต่อ Device
  - ป้องกันการขอเพลงซ้ำในคิวหรือเพลงที่กำลังเล่นอยู่
  - จำกัดความยาวเพลงไม่เกิน 10 นาที
  - ข้ามเพลงให้อัตโนมัติหากวิดีโอไม่ยินยอมให้เล่นแบบ Embed หรือเล่นไม่ได้
  - รักษาข้อมูลคิวคงค้างไว้เมื่อ Server รีสตาร์ต
- 🔒 **แผงควบคุม Admin (`/admin`)**:
  - ป้องกันด้วยรหัส PIN จากไฟล์ `.env`
  - ควบคุมการเล่น (Pause / Resume / Skip)
  - **สวิตช์เปิด/ปิด รับคำขอเพลง** ชั่วคราวได้
  - ลบเพลงรายรายการ หรือล้างคิวทั้งหมด (Clear Queue)
  - แสดง QR Code สแกนเข้าใช้งานผ่าน IP จริงของคอมพิวเตอร์

## 🛠️ ขั้นตอนการติดตั้งและการตั้งค่า (Step-by-Step Guide)

### 1. ติดตั้ง Node.js
ดาวน์โหลดและติดตั้ง **Node.js LTS** (แนะนำเวอร์ชัน 18 ขึ้นไป) จากเว็บไซต์ [nodejs.org](https://nodejs.org/)

---

### 2. วิธีสร้าง YouTube Data API Key ใน Google Cloud Console

1. เข้าไปที่ [Google Cloud Console](https://console.cloud.google.com/)
2. สร้างโปรเจกต์ใหม่ (หรือเลือกโปรเจกต์ที่มีอยู่แล้ว)
3. ไปที่เมนู **APIs & Services -> Library**
4. ค้นหาคำว่า **YouTube Data API v3** แล้วกด **Enable** (เปิดใช้งาน)
5. ไปที่เมนู **APIs & Services -> Credentials**
6. คลิก **+ CREATE CREDENTIALS** -> เลือก **API key**
7. ก๊อปปี้รหัส API Key ที่ได้เก็บไว้

---

### 3. ตั้งค่าไฟล์ `.env`

เปิดไฟล์ `.env` (หากยังไม่มีให้คัดลอกมาจาก `.env.example`) แล้วกรอกข้อมูล:

```env
PORT=3000
YOUTUBE_API_KEY=AIzaSy... (ใส่รหัส API Key จากข้อ 2)
ADMIN_PIN=1234 (รหัส PIN สำหรับเข้าหน้า /admin)
MAX_QUEUE_PER_DEVICE=2 (จำนวนเพลงสูงสุดต่อคน)
MAX_TRACK_MINUTES=10 (ความยาวเพลงสูงสุดไม่เกิน 10 นาที)
REQUEST_COOLDOWN_MINUTES=2 (ระยะเวลาเว้นช่วงการขอเพลง 2 นาที)
```

---

### 4. ติดตั้ง Dependencies

ดับเบิลคลิกที่ไฟล์ **`install.bat`** เพื่อติดตั้ง Dependencies ทั้งหมดผ่าน Command Prompt

---

### 5. เปิดใช้งานระบบบน Windows

ดับเบิลคลิกที่ไฟล์ **`start.bat`**
ระบบจะเริ่มทำงานและแสดง QR Code พร้อม URL บนคอนโซล:

```text
==================================================
🎵 VRS Office Radio (Web YouTube Player Architecture)
💻 Local Machine Access:  http://localhost:3000
📱 Wi-Fi Mobile Access:    http://192.168.1.35:3000
📻 Central Player Page:   http://192.168.1.35:3000/player
⚙️  Admin Dashboard:       http://192.168.1.35:3000/admin
==================================================
```

---

### 6. อนุญาต Windows Firewall

หากมีป้ายเตือน Windows Defender Firewall เด้งขึ้นมาเมื่อเปิดใช้งานครั้งแรก ให้ติ๊กเลือก **Private Networks** และ **Public Networks** แล้วกด **Allow access** เพื่อให้โทรศัพท์ในวง Wi-Fi เข้าถึงเว็บได้

---

### 7. วิธีเปิดใช้งานจากโทรศัพท์พนักงานในวง Wi-Fi เดียวกัน

พนักงานในออฟฟิศเชื่อมต่อ Wi-Fi เดียวกับคอมพิวเตอร์ แล้วสแกน **QR Code** บนคอนโซล หรือ พิมพ์ URL เช่น `http://192.168.1.35:3000` เพื่อเปิดหน้าขอเพลงได้ทันที

---

### 8. วิธีเซ็ตอัป iPhone เครื่องกลาง (+ ลำโพง Bluetooth)

1. นำ **iPhone / iPad เครื่องกลาง** เชื่อมต่อกับ **ลำโพง Bluetooth** ในออฟฟิศ
2. เปิด Safari หรือ Chrome บน iPhone ไปที่หน้า **`http://192.168.1.35:3000/player`**
3. แตะปุ่มใหญ่ **“เริ่มเปิดเพลง”** (Start Music) บนหน้าจอ 1 ครั้ง (เพื่อผ่านข้อจำกัด iOS Autoplay Policy)
4. **ตั้งค่า Auto-Lock เป็น Never**:
   - ไปที่ **Settings -> Display & Brightness -> Auto-Lock** เลือกเป็น **Never** (เพื่อไม่ให้หน้าจอดับ)
5. **เสียบสายชาร์จ iPhone ค้างไว้** ระหว่างเปิดใช้งานในออฟฟิศ
6. **(แนะนำ) เปิดใช้งาน Guided Access**:
   - ไปที่ **Settings -> Accessibility -> Guided Access** แล้วกดเปิด
   - เมื่อเปิดหน้า `/player` ให้กดปุ่ม Power 3 ครั้งติดกันเพื่อเริ่ม Guided Access ล็อคหน้าจอไว้ที่หน้า Player ป้องกันคนกดออกจากแอป

## ⚠️ ข้อจำกัดสำคัญของ YouTube Embedded Player (ตามความเป็นจริง)

1. **สิทธิ์ YouTube Premium ในแอป YouTube Music**: สิทธิ์การเล่นเพลงแบบไม่มีโฆษณาของ YouTube Premium ในแอปพลิเคชัน อาจไม่ถูกส่งมายังเว็บเบราว์เซอร์ภายนอกผ่าน Embedded Player
2. **วิดีโอที่ไม่อนุญาตให้ Embed**: วิดีโอเพลงบางรายการ เจ้าของลิขสิทธิ์อาจปิดกั้นไม่อนุญาตให้เล่นบนเว็บภายนอก หากพบวิดีโอลักษณะนี้ หน้า Player จะแจ้งเตือน และ **ข้ามไปเล่นเพลงถัดให้อัตโนมัติ** โดยไม่ทำให้ระบบล่ม

## คาราโอเกะผ่าน YouTube

- รัน `npm start` หรือ `start.bat` แล้วเปิด `/player` บนคอมพิวเตอร์ที่ต่อจอหลัก กด **เริ่มร้องเพลง**
- เปิดหน้าหลักบนมือถือ ใส่ชื่อผู้ร้องและค้นหาเพลง โดยเปิด **ค้นหาเวอร์ชันคาราโอเกะ** หรือวางลิงก์วิดีโอ/เพลย์ลิสต์โดยตรง
- กด **ขยายจอร้องเพลง** บน Player เพื่อเข้าสู่โหมดร้องเพลง ปุ่มนี้ขยายทั้งหน้าเพื่อให้ QR Code ยังคงแสดงข้างวิดีโอ กด Esc หรือปุ่มย่อเพื่อออก
- QR Code ชี้ไป `https://karaoke.uwaver.site` ตั้งค่าเปลี่ยนได้ด้วย `PUBLIC_URL` ใน `.env` แล้วรีสตาร์ตเซิร์ฟเวอร์ ต้องตั้ง DNS, HTTPS และ reverse proxy ให้โดเมนนี้เข้าเซิร์ฟเวอร์เดียวกันเอง (รวม WebSocket ของ Socket.IO)
- เนื้อร้องและเสียงดนตรีมาจากวิดีโอที่เลือก ระบบยังไม่มีการตัดเสียงร้อง ปรับคีย์ หรือรับเสียงไมโครโฟน
- หากต้องการให้หยุดเมื่อร้องครบคิว ให้ปิด Auto-DJ และการสุ่มจากประวัติวันนี้ในหน้าแอดมิน

## หลายห้องและ QR แยกห้อง

1. เปิด `/rooms` (หรือหน้าหลัก `/`) แล้วสร้างห้องโดยใส่ชื่อห้องและ PIN ควบคุมเป็นตัวเลข 4–10 หลัก
2. ระบบสร้างรหัสห้อง 8 ตัว พร้อมลิงก์ `/?room=รหัสห้อง`, `/player?room=รหัสห้อง` และ `/admin?room=รหัสห้อง`
3. เปิด Player ของห้องบนจอหลัก ผู้สร้างห้องใช้ PIN ที่บันทึกในเบราว์เซอร์ได้โดยอัตโนมัติ ถ้าเปิดจากเครื่องอื่นจะถาม PIN ก่อนเริ่ม Player
4. QR ของ Player และหน้าสร้างห้องชี้ไป `PUBLIC_URL/?room=รหัสห้อง` ผู้ขอเพลงไม่ต้องใช้ PIN และ QR ไม่มี PIN รวมอยู่ด้วย
5. คิว เพลงปัจจุบัน ระดับเสียง สถานะจอ คำสั่งแอดมิน reaction และประวัติวันนี้แยกตามห้อง ประวัติส่วนตัวแยกห้อง ส่วนชื่อผู้ร้องและเพลงโปรดใช้ร่วมกันในเบราว์เซอร์

ห้องหลักเดิมใช้รหัส `main` และคงข้อมูล `data/queue.json` ไว้ ใช้ ADMIN_PIN เดิม ส่วนห้องใหม่ใช้ PIN ของห้องและปิด Auto-DJ/สุ่มเพลงย้อนหลังเป็นค่าเริ่มต้น PIN ของแต่ละห้องถูกเก็บเป็น salted hash ในไฟล์ metadata

ใช้ Node.js/Socket.IO process เดียว แคชค้นหาร่วมกัน ค่าเริ่มต้น MAX_ROOMS=20 (ห้องสร้างใหม่), คิวรอสูงสุด 100 เพลงต่อห้อง, ประวัติ playback 200 รายการและคำขอวันนี้ 500 รายการต่อห้อง ข้อมูลคิวของห้องจะโหลดเมื่อใช้งานและปล่อยออกจากหน่วยความจำเมื่อไม่มีผู้เชื่อมต่อและไม่ได้ใช้งานเกิน 30 นาที โดยตรวจระหว่างคำขอครั้งถัดไป

ข้อมูลห้องเก็บใน `data/rooms.json` คิวแยกใน `data/rooms/รหัสห้อง.json` เปลี่ยนโฟลเดอร์ด้วย KARAOKE_DATA_DIR ได้ การแยกห้องยังใช้ไฟล์ในเซิร์ฟเวอร์: บน Render Free ไฟล์อาจหายเมื่อ restart/deploy ต้องต่อฐานข้อมูลภายนอกหากต้องการเก็บถาวร

ทดสอบทั่วไป: `npm test` การทดสอบ HTTP/WebSocket จริงใช้ `RUN_ROOM_INTEGRATION=1 node --test tests/*.test.js` (PowerShell ตั้ง `$env:RUN_ROOM_INTEGRATION='1'` ก่อน) integration test ใช้พอร์ตและโฟลเดอร์ชั่วคราว ไม่แก้คิวจริง

## ให้ผู้ใช้จัดคิวร่วมกัน

ในแอดมินของแต่ละห้อง เปิด **การตั้งค่าระบบ → อนุญาตให้ผู้ใช้จัดคิว** (ค่าเริ่มต้นปิด) เมื่อเปิด ทุกคนในห้องจะเห็นปุ่มจับแบบจุดที่ทุกเพลงในคิวรอร้อง รวมเพลงที่คนอื่นขอ จับแล้วลากไปตำแหน่งใดก็ได้ด้วยเมาส์หรือจอสัมผัส มีการเลื่อนหน้าจอตามเมื่อเข้าใกล้ขอบ หรือโฟกัสปุ่มจับแล้วใช้ลูกศรขึ้น/ลงบนคีย์บอร์ด เพลงที่กำลังเล่นไม่ถูกย้าย และการลบเพลงยังทำได้เฉพาะผู้ขอเหมือนเดิม

สิทธิ์นี้บันทึกแยกตามห้อง เซิร์ฟเวอร์ตรวจทุกคำขอเลื่อนคิวและปฏิเสธทันทีเมื่อแอดมินปิด การลากบันทึกลำดับในครั้งเดียวโดยตรวจเทียบคิวตอนเริ่มลาก หากคิวเปลี่ยนหรือแอดมินปิดสิทธิ์ระหว่างลาก จะยกเลิกและแสดงคิวล่าสุดแทนการเขียนทับ กด Escape เพื่อยกเลิกการลากได้ แอดมินยังจัดคิวได้ตลอดโดยไม่ขึ้นกับสวิตช์ผู้ใช้

## ลิสต์เพลงฮิตน่าร้อง

แท็บ **เพลงฮิต** มีลิสต์ที่จัดจากไฟล์เพลงที่ผู้ใช้ให้มา 399 รายการ เหลือ 398 เพลงเมื่อรวมรายการซ้ำชื่อและศิลปินเดียวกัน แบ่งเป็น 4 หมวด: อกหักอินเนอร์มา, คลั่งรัก, ฮิปฮอป/สายเต้น และลูกทุ่ง/สามช่า เพลงที่อยู่หลายหมวดยังปรากฏในหมวดที่เกี่ยวข้องครบ ชื่อและศิลปินคงตามต้นฉบับ ไม่ใช่ชาร์ตอันดับสด

ค้นหาในลิสต์ด้วยชื่อเพลง/ศิลปินและกรองหมวดได้ แตะปุ่มค้นหาข้างเพลงเพื่อใช้ชื่อเพลงพร้อมศิลปินค้นหา YouTube ตามสวิตช์คาราโอเกะปัจจุบัน แล้วเลือกวิดีโอก่อนเพิ่มเข้าห้อง ไม่เดารหัสวิดีโอและไม่ค้นหา YouTube ล่วงหน้าทั้งลิสต์

ข้อมูลอยู่ที่ public/data/hits.json โหลดเฉพาะเมื่อเปิดแท็บ แสดงเริ่มต้น 20 รายการและเพิ่มครั้งละ 20 อัตโนมัติเมื่อเลื่อนใกล้ท้ายลิสต์ รองรับทั้งการเลื่อนหน้าบนมือถือและการเลื่อนในกรอบบนคอม พร้อมข้อความเมื่อแสดงครบ ส่วนอันดับจากคำขอจริงของห้องอยู่ในหัวข้อยุบได้ **เพลงที่ห้องนี้ร้องบ่อย**
